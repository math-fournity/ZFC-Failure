# 规则、工具与复现

## 1. 这十天固化的工程纪律（最重要的一节）

### 1.1 MinerU 与视觉审计的分界线

**一句话**：MinerU 拿全文，视觉审计只对实际引用的句子。

**为什么**：几百页的 MinerU 解析是常态且已可靠；但"逐字确定"只需要几条管线比对。
把两者混同会导致两种浪费——该整册解析的只做了几页，或该只核几句的跑去逐页审几百页。

**操作规则**：

1. 任何 PDF/扫描件读取、OCR、转 Markdown、引用，一律先走全局 `mineru` skill；
2. **大 PDF（>200 页）必须用 `~/.agents/skills/mineru/scripts/parse_large.py` 按页范围分片请求，
   禁止物理拆分 PDF 文件**；
3. 直接调 CLI 时 `--limit` 必须显式传大值（脚本内置 `1e8`；CLI 默认约 28872 字符会**静默截断**）；
4. `--wait` 用 600；
5. 视觉审计只做引用句，且**必须机械化比对**（见 §1.2）。

### 1.2 机械化比对（三次教训换来的）

**规则**：任何书面声明里的"逐字一致"，必须附带可重跑的匹配命令与口径；
任何"某人说过某句"的引用，必须做归属回验。

**本 repo 使用的三种口径**（按严格程度递增）：

| 口径 | 做法 | 适用 |
|---|---|---|
| 字母流 | 去空白/连字符/Unicode 组合符/LaTeX 记号后比对 | 跨 OCR 噪声的句子级比对 |
| 子句级 | 把长句拆成子句分别比对 | 中间有 LaTeX 或符号嵌入时 |
| 归属自检 | 同一句在多个候选源里分别搜，确认只在归属源命中 | 引一手/二手文献时 |

**实际样例**（可直接抄）：

```bash
# 字母流比对（柯西定义句）
python3 - <<'PY'
import re, unicodedata
def letters(s):
    s = unicodedata.normalize('NFD', s)
    s = ''.join(c for c in s if not unicodedata.combining(c))
    return re.sub(r'[^a-z]', '', s.lower())
q = "s'approche indéfiniment d'une certaine limite s"
print(letters(q) in letters(open('S2.txt', encoding='utf-8').read()))
PY
```
