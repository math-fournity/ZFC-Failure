## 1. 更正：opencode 克隆不是“历史改写前、推上去会带回删掉的内容”

10-15 我在三处写过这个理由，这里更正：002 §5、005 当夜条目、本目录 `工作台.md`。

**事实**（`tools/opencode_lfs_equivalence.sh`、`tools/lfs_object_on_github.sh`）：

- `/Volumes/D/HoTT_AI_HANDOFF_20260911-opencode/repo` 的 `main` 共 18 个提交。它们与 `dev` 历史开头的 18 个提交一一对应：说明、时间、作者全同。
- 每对提交的树只差两样：一是 `.gitattributes`；二是 `archive/objects.pack`，克隆里是 217,002,151 字节的原件，仓库里是 LFS 指针。指针的 sha256 `3cdaeaf8…` 与原件相同。
- GitHub LFS 上有这个对象：batch 接口返回下载地址。

**所以**：那次“历史改写”是 Git LFS 迁移，没有删掉任何内容。opencode 克隆的全部内容早已在 GitHub 上。原样推送推不上去，因为单个文件超过 100 MB；它的推送地址设成 `DISABLED`，大概也是这个原因。

10-21 补推了 `opencode/main-lfs-equivalent` → `7c447ca6`，即它的 `main` 的 LFS 等价形态。GLM 会话 10-15 的 16 号审计也已判它为“只读镜像、无遗漏”。
