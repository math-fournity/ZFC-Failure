# 第三框架检验：已有证据能支撑多少（2026-10-19）

> **身份**：〔我们的分析〕+ 既有〔机器已证〕证据的调配评估。**不是新命题、不是新收据。**
> **它回答什么**：`docs/H深化-…-20261017.md` §7 的可检验预测——"典范性义务逐层延伸的框架
> 被迫过程读法、暴露 H；典范形式有限的框架终局读法自足、H 不可检测"。
> **结论先说**：**该预测已被既有证据部分检验，且方向一致；但真正能称为"第三框架检验"的
> 对抗性测试仍缺一个实例。**

## 0. 为什么现在做这个

`docs/为什么没有发现-一手层综合-20261019.md` §2 (c) 说"一旦框架要求逐层记账，H 立刻显形"。
这句话的**可反驳点**就在 §7：若能找到一个典范性义务逐层延伸、H 却不暴露的框架，机制就被削弱。
本周盘点既有形式化资产，发现**这个检验已经部分做过了，只是从未被称为检验**。

## 1. 预测的两个半句，各自对应的既有证据

### 1.1 半句 A：「典范形式有限的框架（经典一阶/集合论语言）终局读法自足、H 不可检测」

**对应既有证据**（均〔机器已证〕）：

| 证据 | 它证明什么 | 对应关系 |
|---|---|---|
| C-72（`castIsId`、`noFlip`、`universeIsSet` 全为 `rfl`） | Lean UIP 内核里 cast 是恒等、宇宙是集合 | **平坦相等 ⟹ 完成零代价**的最直接实例：连证明都是 `rfl` |
| C-65（`coh2` 证明为 `fun _ … => rfl`） | 同一六边形定义自动相干 | 同上，平坦侧无需额外记账 |
| C-112 (c)（截断宇宙上同一搜索第 1 问停） | 换到平坦语义后过程面停 | 终局读法自足的机器形式 |
| C-437 侦察（`lean` core 零公理） | "命名 = 定义展开"在 core 可判定 | 平坦侧完成操作是定义展开，不是新结构 |

**评估**：半句 A 的支撑**相当强**，且有 `rfl` 级的内核证据。

### 1.2 半句 B：「典范性义务逐层延伸的框架被迫过程读法、暴露 H」

**对应既有证据**：

| 证据 | 它证明什么 |
|---|---|
| C-78（宇宙上追问 ≡ never） | 分层结构暴露 H |
| **C-81 (c)**（`productQuestioningIsNever`：非宇宙的 EM 空间乘积上，同一追问仍 ≡ never） | **同一个程序、换掉被追问对象，H 仍暴露** |
| C-83 (d)（`noDecoding`） | 截断不能把显形面关回去 |

**C-81 是本节最重要的证据**：它把 H 的暴露从"宇宙"扩展到
**HoTT Book 例 8.8.6 的乘积**（一族 EM 空间的无穷乘积），
并且判定器**唯一**（`everyJudgeIsJudgeProd`）+ 内核实跑 1000 步（`refl`）。
这说明 H 的暴露**不依赖"被追问的是宇宙"这个特殊身份**。

### 1.3 关键发现：C-81 (d) 正是预测中的那个判别器

`H深化` §7 的分野判据是"**典范性义务是否延伸到过程每层**"。
C-81 (d) 给出了这个判据的机器形式——它对照**两个问法**：

- 问「第 k 层落定了吗？」→ 永不停（`productQuestioningIsNever`）；
- 问「有没有一层落定？」→ **一步不走就答"没有"**（`productWhetherAnswersNo : runFor 0 … ≡ just false`）。

**同一个数学事实（乘积无有限 h-level），两种问法的计算代价天差地别。**
这正是 §7 预测要说的话：**H 是否显形取决于问的是终局还是过程**，
而不取决于事实本身是否已知。`H深化` §4.1 的"∃N 把有限前缀整个装箱丢弃"有了精确对照物。

## 2. 这个检验还缺什么（对抗性实例）

现有证据全部是**正面**的：分层 ⟹ 暴露、平坦 ⟹ 不暴露。
按 `最高指示` §0A/§5 的要求，发现态之后必须有**对抗性检验**：

- **缺一个"典范性义务逐层延伸但 H 不暴露"的候选框架**。
  若存在且被机器检查，`为什么没有发现` §2 (c) 的机制就被**削弱**（不是推翻——
  它仍是两个实例的合理解释，但失去"一旦要求逐层记账就立刻显形"的强度）。
- 候选方向（`H深化` §7 已点名）：**coinduction / 非良基集合**、
  构造性类型论的其他变体（如定时类型论的 guarded 递归）、有向类型论。

**repo 内已有有向类型论资产**（`directed-reading` C-34–C-38、`directed-native` C-45、
`directed-interface-rzk`、`time-direction`），但盘点后确认：**它们不适用**。
它们的主题是"读数沿有向旅程的形状约束"（箭头塌缩、互逆对、抽象冻结），
**不涉及典范性义务是否逐层延伸，也没有 `Arrives`/`Never` 或 h-level 追问结构**。
把它们算作"第三框架"会是**张冠李戴**。

### 2.1 第三轮消融：`--guardedness` 是不是"另一个演算"？——**不是**

第 2 轮（§3.1 结论一）把 `pedometer-semantics` 判为"第三框架的正面实例"，
理由正是它带 `--guardedness`。本轮做**消融实验**检验这个判断：

| 实验 | 命令 | 结果 |
|---|---|---|
| 保留 `--guardedness` | `agda --cubical -i . -i <cubical-v0.9> PedometerSemantics.agda` | **exit 0**，无输出 |
| 去掉 `--guardedness` | 同上，仅改 OPTIONS 首行 | **exit 42**，`[InfectiveImport]`：`Importing module Cubical.Foundations.Prelude using the --guardedness flag from a module which does not` |

**但失败的根源不是该文件需要 guardedness，而是 cubical 0.9 库本身是带 `--guardedness` 编译的**，
Agda 对该 flag 是 **infective** 的——任何消费者都必须开。
所以这个消融**不能**证明"该文件的证明依赖 guardedness"。

**更直接的证据**：在该文件里逐个数 guardedness 专有构造：

| 构造 | 出现次数 |
|---|---|
| `♯` / `sharp` / `Löb` / `loeb` | **0 / 0 / 0 / 0** |
| `Tick` / `tick` / `▹` / `▶` | **0 / 0 / 0 / 0** |
| `laterElim` / `isFixedPoint` | **0 / 0** |
| `later` | **仅作数据构造子**（:66 声明、:75 定义 never、:80-81 evalFor、:97 step） |

而 C-55 (a) 的核心证明是：

~~~text
diverges : (k : ℕ) → searchFrom k ≡ never
diverges k i .force = stepNever k (dec k) i
~~~

它用的是 **path (`≡`) + 协归纳记录的投影 (`force`)**，
**没有用到 guardedness 的任何推理规则**（无 Löb 原理、无 sharp、无 tick 演算）。

**因此修正第 2 轮的判断**：
`pedometer-semantics` **不是**一个"典范性义务不同的第三演算"。
它是**同一个 Cubical Agda 内核**里的一个**协归纳数据类型**（Capretta delay monad），
`--guardedness` 只是该 cubical 发布版的构建 flag，**不构成独立的类型论变体**。

**这反而使 `H深化` §7 检验的结论更干净**：
- 该包证明的「`program ≡ never` 是一条路径」仍然成立、仍然有价值——
  它说明**在同一个内核里**，"逐层"可以被做成类型构造子并被如实记账；
- 但它**不能**被算作"第三框架的正面实例"，因为框架没变；
- **§3 结论 1 的"部分检验"范围退回第 1 轮的状态**（C-78/C-81/C-83），
  第 2 轮新增的那一条证据**不是框架层证据**。

### 2.2 第四轮真消融：`--guardedness` 对**定义**是 load-bearing 的（修正第 20 轮）

第 20 轮 §2.1 说"本机无法用删 flag 隔离 guardedness 是否被证明依赖，
因为 cubical 0.9 库本身带该 flag（infective）"，并把结论建立在**构造计数**上。
**本轮发现那个判断过弱：可以做一个不依赖 cubical 库的真消融。**

用纯 Agda builtin（`Agda.Builtin.Nat`，无 cubical）写最小复现：

~~~text
module CoindProbe where
open import Agda.Builtin.Nat
mutual
  data D' (A : Set) : Set where
    now   : A -> D' A
    later : D A -> D' A
  record D (A : Set) : Set where
    coinductive
    field force : D' A
open D
never : {A : Set} -> D A
never .force = later never
step : D Nat
step .force = later step
~~~

| 运行 | 结果 |
|---|---|
| `agda --safe -i . CoindProbe.agda`（**不开** `--guardedness`） | **exit 42，两处 `[TerminationIssue]`**，Agda 自己提示 `(Option --guardedness might fix this problem.)` |
| `agda --safe --guardedness -i . CoindProbe.agda`（**开**） | **exit 0，无错误** |

**结论（修正第 20 轮）**：`--guardedness` 对 **`never` 与 `step` 这两个定义本身**是 **load-bearing** 的。
没有它，连"永不停机的程序"这个对象都无法通过终止检查。

**但这仍然不使 `pedometer-semantics` 成为独立演算。** 判据要分清两件事：

1. **定义层**：`never`/`step` 的合法性依赖 `--guardedness`（本轮已证）。
2. **推理层**：`pedometer-semantics` 与 C-55 (a) 的**证明体**用了什么？
   第 20 轮的构造计数仍然成立——`♯`/`Löb`/`Tick`/`▹`/`laterElim` **全为 0**，
   `diverges k i .force = stepNever k (dec k) i` 用的是 path + 记录投影。

**所以修正后的准确说法是**：
`--guardedness` 是该 cubical 构建的**必需构建 flag**（对定义 load-bearing，
Agda 的 guardedness 扩展为协归纳定义放行），
但 `pedometer-semantics` 的**证明**并未使用 guardedness 专有的**推理规则**。
它因此**处于同一个类型论的一个扩展构建配置里**，而不是"另一个演算"的另一个内核。

**这个区分为什么对 goal 要紧**：如果把"开了某个构建 flag"当成"换了框架"，
那 §7 的第三框架检验就被稀释成"换个命令行参数"。
框架层判据必须是**推理能力的变化**（能否陈述/证明原先不能的东西），
而不是**定义合法性开关**。按这个判据，`pedometer-semantics` 仍不算第三框架，
**§3 结论 1 的范围维持第 20 轮的修正**（退回 C-78/C-81/C-83）。

### 2.3 本轮暴露的第 20 轮错误（照实）

第 20 轮写"本机无法用删 flag 隔离依赖性（库 infective）"。
**这句是错的**：隔离方法不是"删掉 consumer 的 flag"（那会 InfectiveImport），
而是"写一个不 import cubical 的最小复现"。
第 20 轮在 §4.4 把一个**方法限制**说成了**不可能**，
导致结论只靠构造计数这一条腿。本轮补上第二条腿，且它**加强**了
"guardness 是真的"这一半、同时**不改变**"不是独立演算"的最终判据。

## 3. 评估结论

1. **`H深化` §7 的预测已被既有证据部分检验，方向一致**：平坦侧有 `rfl` 级证据，
   分层侧有 C-78/C-81/C-83；C-81 (d) 还提供了预测中那个判别器的机器形式。
2. **但"第三框架检验"仍未完成**：缺对抗性实例。**不得**因为方向一致就宣称预测已验证。
3. ~~**coinduction / guarded 递归方向在本 repo 无现成资产**~~
   → **第 2 轮已证伪（§3.1）**：`pedometer-semantics` 确实存在且用 delay monad；
   → **但第 3 轮再修正（§2.1）**：消融实验证明它**不是独立演算**——`--guardedness` 只是
   cubical 0.9 发布版的构建 flag（infective），该文件的证明只用 path + 协归纳记录投影，
   无 Löb/sharp/tick。**所以它不算第三框架的正面实例，§3 结论 1 的范围退回第 1 轮。**

## 3.1 本轮补做：穷举全部 51 个包后的两个新结论（2026-10-19 追加）

第 1 版本文有未闭合项 3：「只盘点了 `claude-cg001/` 与部分顶层包，未穷举全部 40+ 包」。
本轮机械穷举 **`ls -d HoTT/formal/*/` = 51 个包**（`claude-cg001/` 内再分 71 个子包），
按三个检索面扫：`isOfHLevel|hLevel`、`question|Never`、`▷|later|Löb|Delay|guarded`。

**结论一：第三框架其实一直都在 repo 里，我第 1 版漏了它。**

`HoTT/formal/claude-cg001/pedometer-semantics/`（**C-55/C-56/C-59**）用的正是
**guarded / coinductive 演算**——源码首行 `{-# OPTIONS --safe --cubical --guardedness #-}`，
其核心是 Capretta 2005 的 delay monad：

~~~text
mutual
  data Delay' (A : Type) : Type where
    now   : A → Delay' A
    later : Delay A → Delay' A
  record Delay (A : Type) : Type where
    coinductive
    field force : Delay' A
never .force = later never
~~~

(`PedometerSemantics.agda:64-75`)

**它是怎么加强（而不是削弱）预测的**：在这个框架里，"过程每一层"**确实是类型的一部分**——
`Delay` 是协归纳记录，`force` 逐个展开，永不停机的程序是 `never`（`later never` 无限展开）。
而 C-55 (a) 的 `diverges`/`programIsNever` 给出的是 **`program ≡ never`，即 delay 类型中的
一条路径（bisimilarity）**——不是"跑不完"，是"等于那个永远跑不完的程序"。

**这正是 `H深化` §7 预测在第三框架上的成立实例**：典范性义务逐层延伸
（`later` 一层就是一个构造子）⟹ 过程面必须被如实记账 ⟹ H 显形（`≡ never` 可证）。
而对照：C-112 (c) 的截断宇宙上同一个搜索第 1 问就停——**同一程序换到平坦语义，过程面消失**。

**结论二：但这仍然不是对抗性检验。**

第 1 版 §2 要的是「典范性义务逐层延伸**而 H 不暴露**」的实例。delay monad 是**正面**实例
（逐层 ⟹ 暴露），与 C-78/C-81 同类。**所以 §3 结论 2 不变：对抗实例仍缺。**
但 §3 结论 1 的范围要改：第三框架的**正面**证据已从"无"变成"有（delay monad）"，
我第 1 版说"coinduction / guarded 递归方向在本 repo 无现成资产"是**错的**——
现成资产就是 `pedometer-semantics`，我漏扫了它。

**第 1 版错误的原因**：第 1 版用 `rg -li "coinduction|coalgebra|non-well-founded|M-type"`
搜，命中里看到 `pedometer-semantics` 却在下一步只看了 `directed-*` 与 `time-direction`，
没有进 `pedometer-semantics/` 读源码。**这是"检索命中后未消费"的疏漏**，
与本周多次抓到的假阴性同型。
